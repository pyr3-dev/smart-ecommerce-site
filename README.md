# Smart Ecommerce Platform

A multi-tenant ecommerce marketplace (think Shopee) where sellers open shops, list products, and receive AI-powered insights into what's driving success — or holding them back. Insights are gated behind a premium subscription and generated by a separate analytics server that processes platform-wide data to surface trends, pricing recommendations, demand forecasts, and competitor benchmarks.

**Stack:** Next.js 15 (App Router) · React 19 · TypeScript · Supabase (self-hosted) · PostgreSQL 15 · Redis · Tailwind CSS · shadcn/ui · Docker Compose

---

## Architecture

```
┌─────────────────────────────────────────────────────────┐
│  Browser                                                │
│  Next.js frontend (port 3000)                           │
└────────────────────────┬────────────────────────────────┘
                         │ REST / Realtime / Auth
┌────────────────────────▼────────────────────────────────┐
│  Kong API Gateway (port 8000)                           │
│  ├─ GoTrue        (auth)                                │
│  ├─ PostgREST     (auto-generated REST API)             │
│  ├─ Realtime      (WebSocket subscriptions)             │
│  └─ Storage       (file uploads)                        │
└────────────────────────┬────────────────────────────────┘
                         │
┌────────────────────────▼────────────────────────────────┐
│  PostgreSQL 15 + Redis                                  │
│  Row-Level Security enforces multi-tenant isolation     │
└─────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────┐
│  Analytics Server (private repo — see below)            │
│  Reads raw user_events + metrics tables                 │
│  Writes insight scores back to DB on a cron schedule    │
│  Premium subscribers see results in the frontend        │
└─────────────────────────────────────────────────────────┘
```

Row-Level Security handles all multi-tenancy and subscription gating at the database layer — no application-level auth guards needed for data access.

## Setup

### 1. Clone and configure environment

```bash
git clone <this-repo>
cd smart-ecommerce-site
cp .env.example .env
```

Open `.env` and fill in every value. Key things to generate:

```bash
# JWT secret (used by GoTrue and to sign ANON/SERVICE_ROLE keys)
openssl rand -base64 64

# Realtime encryption key
openssl rand -hex 64

# Redis password — any strong random string
openssl rand -hex 32
```

For `ANON_KEY` and `SERVICE_ROLE_KEY`, generate them from your `JWT_SECRET` using the tool at:
https://supabase.com/docs/guides/self-hosting/docker#generate-api-keys

> **Supabase Cloud instead of self-hosted?** Skip to the [Cloud Supabase](#using-supabase-cloud-instead) section.

### 2. Apply the database schema

```bash
# Start only Postgres first
docker compose up -d db

# Run the schema migration
docker compose exec db psql -U postgres -d postgres -f /docker-entrypoint-initdb.d/schema.sql
```

Alternatively, paste `supabase/migrations/schema.sql` into the Supabase Studio SQL editor after the full stack is running.

## Running in Development Mode

In dev mode Next.js runs outside Docker with hot reload, while Supabase runs inside Docker.

```bash
# 1. Start the Supabase stack (Postgres, Auth, API Gateway, Studio, etc.)
docker compose up -d db redis kong auth rest realtime storage imgproxy meta studio

# 2. Install dependencies
pnpm install

# 3. Start Next.js dev server
pnpm dev
```

| Service | URL |
|---|---|
| Next.js frontend | http://localhost:3000 |
| Supabase API (Kong) | http://localhost:8000 |
| Supabase Studio | http://localhost:8000 (login with `DASHBOARD_USERNAME` / `DASHBOARD_PASSWORD`) |

Your `.env` should have:
```env
NEXT_PUBLIC_SUPABASE_URL=http://localhost:8000
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<your ANON_KEY value>
```

## Running in Production Mode (Full Docker Stack)

Everything runs in Docker, including Next.js built as a standalone image.

```bash
docker compose up -d --build
```

This builds the Next.js image and starts all services. The frontend is available at port 3000 and the Supabase API at port 8000.

To update the frontend after code changes:

```bash
docker compose up -d --build nextjs
```

To view logs:

```bash
docker compose logs -f nextjs
docker compose logs -f kong
```

## 🔒 Advanced Analytics Server

The core ecommerce platform is fully open source.

The **Advanced Analytics Engine** — which powers subscription insights,
ML-based store performance scoring, and product demand forecasting — is
available as a **separate licensed module** in a private repository.

### What's included
- Store success scoring model (trained on anonymized platform data)
- Product trend analysis pipeline
- Subscription tier API (integrates with this repo out of the box)
- Self-hosting guide + Docker Compose setup

### How it connects

The analytics server:

- Reads raw `user_events`, `store_daily_metrics`, and `product_daily_metrics` tables
- Writes results to `store_insight_scores`, `product_insights`, and `platform_insights`
- Exposes an internal HTTP API consumed by the Next.js frontend
- Runs on a cron schedule (default: `0 2 * * *` — 2 AM daily)

**Without it**, the app runs fully — shops, products, orders, and subscriptions all work. Premium subscribers just won't see populated insight scores until the server is running.

## Using Supabase Cloud Instead

If you prefer Supabase Cloud over the self-hosted Docker stack:

1. Create a project at https://supabase.com
2. Run `supabase/migrations/schema.sql` in the Supabase SQL editor
3. In your `.env`, comment out the self-hosted `NEXT_PUBLIC_*` block and set:
   ```env
   NEXT_PUBLIC_SUPABASE_URL=https://<project-ref>.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=<your cloud anon key>
   ```
4. The Postgres, JWT, SMTP, Redis, and Kong variables are not needed
5. Run `pnpm dev` — no Docker required for the Supabase backend

## Key Design Decisions

- **No application-level auth guards on data** — RLS policies in PostgreSQL enforce that sellers only see their own data, and premium insights are only readable by users with an active subscription at the required plan tier.
- **Supabase client never stored globally** — a new client is created per request to stay compatible with Next.js Fluid compute (no shared state between requests).
- **Analytics is decoupled** — the insights pipeline reads and writes the database directly; the frontend just reads the output tables. The analytics server can be swapped or extended without touching the Next.js app.
